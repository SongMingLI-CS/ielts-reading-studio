# Learning Studio UI Pattern

视觉母版：当前 `/practice`。迁移的是内容优先、任务清楚、界面退后的设计语言。每个页面按自己的任务组织布局。

## 页面标题层级

一个 H1，桌面 30px / 1.24，手机 28px；短说明放在标题下一行，14px，次要色。不再叠加重复 eyebrow、长产品介绍或页头 KPI。标题区下方留 32px，手机约 23px。

## 主任务区域

首屏明确回答“现在做什么”。有正在进行的独立学习对象时可用轻微 surface；输入、复习、查找、配置等任务按自身逻辑布置，不强制添加继续学习卡片。主任务内只保留帮助下一步行动的信息。

## Sidebar 信息架构

桌面约 204px，背景比正文略深，文字 13px。今天单独放置；学习含阅读、写作、复习；资料含知识库、技术学习、语境阅读；低频内容制作和账户能力归入更多。组间距 23px，组内导航行约 32px。手机使用菜单，保留分组，不把所有链接平铺。

## 内容宽度

主内容居中，默认 820px。连续阅读与文章索引约 690px；任务表单 760–820px；需要对比列的数据页可到 960px；配置页约 820px。宽度由内容决定。桌面外侧留 48px，手机 16–24px。

## Section 间距

主要任务与下一组内容之间 40–49px，手机 32–38px；Section 标题与工具约 17px；工具与内容约 22px。用留白区分段落，避免每个 Section 添加横线。

## Article / List Row

先给内容名称或标题，再给来源和当前状态，最后给规模、成绩、时间等辅助信息和局部动作。文章标题桌面 22px Georgia，手机 20px；工具和配置项使用 UI 字体。动作跟随内容，不固定成远端操作列。列表项可用局部 hover surface，不用大量边框。

## CTA 强弱关系

一个当前主任务对应一个实心深绿按钮，约 41px 高、13px 字。普通文章操作为 13px 文字链接；辅助动作采用描边或文字；筛选采用小范围选中 surface。删除、重试和导出只有在相应上下文才出现。

## Metadata 层级

来源与状态 12–13px，辅助数据 12px，使用更弱但可读的色彩。同类短信息用间隔或中点组合。正文信息不要全部铺成标签、字段、计数器。进度使用 3–4px 轻量条，并附文字。

## Surface 使用条件

独立学习对象、正文输入区、当前复习题和需要集中注意的配置组可以有 surface。母版 surface 为暖白色、1px 浅边、8px 圆角、无阴影。普通 Section、标题区、列表无需 surface。避免 surface 嵌套。

## Divider 使用条件

只在会产生阅读歧义的边界使用：数据表行、配置项分组、危险操作区、独立工作流之间。普通内容段落和文章列表使用留白。不要用横线替代所有 Card。

## Typography 层级

H1 30px；Section 标题 21px；文章标题 22–24px serif；工具名称 15–18px UI 字体；正文 14–16px，阅读正文行高 1.7–1.8；来源、状态和数据 12–13px。粗体用于标题与动作，普通正文避免统一加粗。

## Mobile 折叠策略

900px 以下侧栏进入菜单；700px 以下多列变单列，标题说明仍保留；搜索与筛选分行，筛选可横向滚动；文章动作跟随元信息换行；低频选项用原生 details。正文和主要操作不隐藏。手机表格只有确实依赖列对比时横向滚动，否则转成带标签的记录。

## 按页面类型选择布局

- 阅读型：宽度受限，正文与内容标题主导；章节、检索和笔记为辅助。
- 任务型：输入或当前题目主导；过程状态就地出现；完成结果按阅读顺序呈现。
- 数据型：保留有比较价值的列；标题、状态、关键动作先于内部标识和技术字段。
- 配置型：按用途分组，标签与值易于对应；组间留白，组内必要分隔；保存与连接动作明确。

## 迁移顺序与分类

1. 写作反馈：任务型，作文编辑与反馈阅读。
2. 复习：任务型，当前待复习内容与回忆操作。
3. 知识库：阅读型，检索、收藏与阅读资料。
4. 技术学习：阅读型，文档阅读、学习进度与笔记。
5. 语境阅读：阅读型，书籍与章节阅读；生成能力为次级任务。
6. 材料：数据型，材料状态与下一步制作操作。
7. 生成任务：数据型，运行状态、失败原因与恢复操作。
8. 设置：配置型，模型连接与应用选项。

## 截图验收

每次只迁移一个页面，截图检查后再继续。先判断主任务是否清晰，再判断页面是否保留自身逻辑。关注标题层级、主次动作、字段密度、横线数量、Surface 是否有真实内容边界，以及手机首屏能否开始主要任务。测试通过只确认功能，不能替代视觉验收。
