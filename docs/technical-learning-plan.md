# 技术文档学习实施计划

目标：把 Python → NumPy → AI 的官方文档变成可持续学习的材料，同时保留原文和代码。

## 1. 文档来源与存储

- 增加独立技术文档库，不经过小说的文章改写流程。
- 支持 Python、NumPy、scikit-learn、PyTorch 官方 HTTPS 文档和 Markdown 文件。
- 保存章节、代码、参数定义、表格、来源 URL、版本标记、导入时间与内容哈希；同一快照重复导入复用已有记录。
- 外部 HTML 只提取内容，不渲染脚本或任意 HTML；检查每次跳转和下载大小。

## 2. 阅读与学习

- 三阶段入口：Python 基础、NumPy 数组、AI / 机器学习。
- 章节导航、原文阅读、代码复制、版本及来源展示。
- 按当前章节生成双语词汇、概念讲解、英语与概念自测，题目证据必须来自原文。
- 原文与讲解分开保存；讲解缓存，学习进度、笔记和自测结果持久化。

## 3. ScholarKernel 与产品文案

- 复用已部署的研究对话接口；讨论来源包含文档的官方 URL 和版本。
- 选中当前原文携带问题进入 ScholarKernel。
- 首页分别标明技术学习和 ScholarKernel 的真实可用状态，导航增加入口。

## 4. 验证与发布

- 覆盖内容提取、代码保留、来源限制、重复导入、生成证据、进度恢复、自测评分与 CSRF。
- 数据库增加向前兼容迁移，现有材料与练习不变。
- 运行离线验证；检查桌面及手机布局；真实导入官方页面。
- 提交、推送主分支，部署前备份数据库，迁移并验证生产服务。

本轮范围：完成上述可用流程；代码示例用于阅读和复制，不运行用户代码。

## 实施记录

上述四阶段的功能已实现，入口为 `/learn`。官方地址导入不调用模型；只有点击章节的“生成本节讲解与自测”才调用模型，结果保存复用。

已通过 754 项离线测试、Ruff、编译和 CLI 验证；实际读取 Python、NumPy、scikit-learn 入门文档，核对代码保留、网页进度与笔记刷新恢复。已检查默认桌面视图及 390 px 手机视图，手机文档宽度没有溢出。

真实模型验证发现引用可能合并原文换行。校验现在只允许空白差异，并恢复原文中的精确引用片段；不存在于原文的证据仍然拒绝保存。

## 文档容量与完整学习路径

根据使用反馈，初版的 2 MB 文件限制和单页入门入口不足以支持手册学习。本次调整：

- Markdown 文件默认最大 100 MB，可通过 `web_learning_max_upload_bytes` 配置，实际限制同时受 `web_max_upload_bytes` 约束。逐块读取，解析与存储在线程池执行；单个远程 HTML 页面独立限制为 10 MB。
- 推荐入口导入多篇原文组成的学习路径：Python 官方教程全部 16 章；NumPy 入门、快速上手及 9 个基础主题，共 11 篇；scikit-learn 的 7 篇核心指南。后两者是明确选定的章节集合，不宣称覆盖全部 API 手册。
- 每篇保留官方 URL 与版本，整套按固定顺序保存；任一篇失败或版本不一致则不保存部分教程。每次最多并行下载 3 篇。
- 默认连续阅读，支持完整目录与前后分页；每页最多 60,000 字符或 40 节。分节学习保留讲解、自测、笔记及已读状态。分页只影响显示，不截断保存内容。
- 新导入的长章节按约 12,000 字符拆分，保留文本、代码顺序与空行，使模型上下文保持完整。既有文档与进度不重新分段。
- 文档卡片标明来源篇数、小节数和字符数；文档库仅查询元信息，避免反序列化所有手册全文。连续阅读中选中原文讨论时，ScholarKernel 接收对应章节的官方来源。

已实际读取 34 篇官方页面：Python 232,779 字符、NumPy 219,715 字符、机器学习 314,490 字符。768 项离线测试通过，包括超过旧上限的文件、超限拒绝、全文尾部保留、分页不漏节、版本一致性和旧数据兼容。

另在独立本地数据库中实际上传了恰好 100 MB 的 Markdown 文件，确认导入成功、最后一段原文仍在、文档库正常返回、阅读页只渲染当前分页正文。大文件元信息通过单次 JSON 路径提取查询，避免数据库为多个元信息字段分别保留全文解析副本。
