IELTS Learning Studio 的设计基础值得保留。真正需要优先改变的，不是配色，而是入口层级、首屏可操作性和答题布局的可靠性。

01 / 评审范围与边界

检查站点外壳、首页、材料库、练习中心、在线答题、结果解析、知识点与写作界面；结合路由、表单及样式级联分析。预览使用独立数据库副本，不调用模型，不更改原有学习记录。

代码证据与视觉验证分别标注。本文属于启发式评审，不包含用户访谈、真实转化率测量或完整无障碍认证。方案中的首屏与操作步数属于建议验收目标，不是已证明的收益。

02 / 值得保留的基础

不要推倒重做。

已有语义明确的主按钮与状态标签；练习支持双栏阅读、可调分隔线、浏览器草稿与服务器保存；支持未答题跳转、漏答确认、原文证据和中文解析；材料生成有样篇批准门槛；部分控件已具备焦点样式、触控适配和减少动态效果支持。

下一版应延续这些能力，优先处理“能力存在但入口难找”与“视觉正常但交互不可用”的问题。

03 / 问题清单与优先级

P0：关键任务可靠性，发布前修复；P1：核心体验与信任问题，下一迭代处理；P2：一致性与效率优化。

P0

01. 小屏答题布局的 CSS 级联存在冲突

问题：早期媒体查询设置单栏，但后置通用规则重新定义三列；后面的移动分栏样式只隐藏面板，没有重设网格。实测已确认空列与窄阅读区：390px 视口下容器可用宽 364px，却保留 320 / 12 / 390px 三列；768px 视口下文章区域仅宽 332px，右侧大块留白。此处不是推测，也不应仅靠隐藏横向滚动条处理。

方案：默认单栏，在 ≥1025px 的媒体查询中才开启双栏与分隔条；隐藏的面板不保留轨道。手机保证全文和题目都能使用完整内容宽度；平板另行验证，而不是简单等同手机。

代码证据：static/app.css:12–15, 63, 84–94。实际尺寸验证见后文。

P0

02. 安全策略与内联事件冲突，部分按钮和确认可能失效

问题：严格脚本策略下，HTML 的 onclick / onchange / onsubmit 不被允许。受影响的是打印、分页自动提交及章节合并/拆分确认，不能仅视为视觉瑕疵。

方案：使用同源外部脚本绑定事件；不要放宽脚本安全策略来迁就旧写法。对章节修改保留明确确认，对打印保留可见按钮及说明。

代码证据：app/security/headers.py:42；templates/corpora/preview.html:75, 138, 146；三个独立打印模板的内联 onclick。未实际执行章节修改。

P1

03. 12 个一级导航混合学习与管理任务

问题：阅读、写作、知识点和导入、备份、设置处于同一层；移动端隐藏滚动条的横滚导航缺少“还有入口”的提示。用户必须先理解系统模块。

方案：按“学习”与“内容管理”拆分。常驻学习首页、阅读、写作、知识库、情境小说；材料、生成任务、审阅、导出放入内容管理；备份、设置和退出进入账户菜单。手机使用 4 个稳定入口：首页、阅读、复习、更多。

代码证据：templates/base.html:19–32；static/app.css:20–24。

P1

04. 首页像介绍页，练习中心的操作出现得太晚

问题：首页大标题加大尺寸产品卡，三项产品却采用两列网格，写作入口落到下一行。练习中心先展示介绍、私有存储与统计，再展示篇目；≤390px 又把四个统计格拆为单列。

方案：首页第一屏展示“继续上次学习”；有草稿优先继续，无草稿显示推荐篇目，无内容则引导导入。练习中心压缩标题区域，把统计变为一行摘要，进行中的篇目置顶；增加状态筛选与搜索。

代码证据：templates/home.html:4–38；static/studio.css:1；templates/practice/index.html:4–24；static/practice-center.css:17–18。

P1

05. 无障碍能力不均衡，浅色小字需要校准

问题：无跳过导航入口；答题页文本输入/下拉框缺少与题干的程序化关联；移动标签缺少完整面板关联与方向键切换；词汇卡用不可聚焦的 article 承担点击展开。

方案：增加 skip link；为题组/输入提供 legend、label 或 aria-labelledby；标签与面板关联，支持方向键；词汇展开改用 button 或 details/summary；保存反馈采用状态播报。辅助文字使用更深的中性色。

代码证据：templates/base.html:17–35；templates/practice/session.html:27–32, 51–62；static/practice.js:241–246；templates/practice/analysis.html:34–41。颜色计算：#7d8a85 / 白底约 3.59:1，#8b948f / 白底约 3.12:1；建议常规正文至少 4.5:1。

P1

06. 状态说明暴露实现细节，任务结束缺少清晰下一步

问题：任务页直接使用任务 ID 作标题、显示原始状态与 worker 信息；材料卡只展示最近任务文本而非可点击入口。结果页写“这台电脑的 SQLite”，与其他页面“私有服务器”说法混杂；首页还残留“两个工具”的旧文案。

方案：用“某材料 · 第 1–10 章生成任务”命名，显示已完成/总数、失败原因及下一步；完成后主按钮为“开始练习”，失败时提供“重试失败项”。统一“浏览器暂存”与“已同步到私有服务器”，技术详情折叠。

代码证据：templates/jobs/detail.html:4–7；templates/corpora/index.html:91；templates/practice/result.html:21；templates/home.html:40。

P2

07. 多个知识入口命名接近，结果页未突出复习任务

问题：词汇、知识点、练习生词本与错题分散在不同层；用户容易疑惑内容区别。结果页主操作是“重做本篇”，还未把错题复习作为主线。

方案：统一归到“知识库/复习”，保留错题、已收藏词汇、自动汇总知识三个清晰标签，不合并底层数据语义。结果页先给题型表现与薄弱点，再“复习错题”；全部正确时改为“下一篇”。

代码证据：templates/base.html:24–25；templates/practice/index.html:9；templates/practice/result.html:16–24。

P2

08. 视觉令牌已有雏形，但字号、密度和断点尚未统一

问题：多个样式文件重复覆盖通用规则；标题装饰、卡片留白、英文辅助标题占据较多空间。小字颜色、圆角、按钮样式分散定义，调整时容易造成跨页回归。

方案：保留绿色品牌，明确中英文角色；中文界面用系统无衬线，英文长文保留阅读字体。统一 4/8px 间距、3 档标题、正文/辅助文本、按钮与状态组件；把断点和覆盖关系收敛到一处。

代码证据：static/app.css:1, 9–40, 84–103；static/practice-center.css:1–22, 136–148；static/studio.css:1, 10–11。

06 / 分阶段执行，而非一次性翻新

阶段 A · 修复可用性

先守住核心任务

  • 移动/平板网格级联
  • 内联事件与脚本策略冲突
  • 输入标签、焦点和保存状态
  • 补桌面及小屏回归检查

完成标志：阅读、答题、确认和打印不再被布局或事件阻断。

阶段 B · 重构信息层级

围绕“下一步”布局

  • 学习 / 内容管理分层
  • 首页继续学习卡
  • 练习中心压缩、筛选与搜索
  • 任务重新进入和结果复习路径

完成标志：学习主操作在首屏，管理任务可以被找回。

阶段 C · 统一视觉系统

提升一致性与可维护性

  • 统一字体、间距、状态色
  • 组件与断点去重
  • 知识库命名和帮助文案
  • 建立页面与状态截图基线

完成标志：同种控件跨页面同样呈现、同样操作。

建议指标：进入练习所需步骤、恢复草稿成功率、未答题发现率、移动端横向溢出数量、任务找回成功率。先记录基线，再验证优化效果；不预设“效率提升百分比”。

08 / 伴随发现：不混入视觉改版

部分 GET 筛选表单包含 CSRF 隐藏字段，提交后可能把令牌带入 URL。应单独作为工程修复项移除 GET 表单中的该字段；不能因此削弱 POST 的 CSRF 保护。证据：templates/knowledge/index.html:48、templates/corpora/preview.html:73/81 等。本次未进行完整安全审计。

你的两点反馈分别是「有些东西只有三块，自然空出一块地方」和「失败原因等等都不够清晰」。第一点查到的是上一轮修复没真正到达你的浏览器，第二点确实是文案设计问题。

一、留白的根因：浏览器手里还是旧样式

第二轮把书库样式从媒体查询里搬到了顶层，线上 CSS 也确实是新的（拿服务器上的 studio.css 按花括号深度取顶层选择器，.book-library / .book-row / .book-badge / .pagination-pages .page-number 都在），可你看到的仍是旧行为。原因有两层：
